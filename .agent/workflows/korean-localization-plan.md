# ChatVRM 프로젝트 한글화 검토 보고서

## 1. 프로젝트 개요
- **프레임워크**: Next.js 13.2.4
- **언어**: TypeScript
- **UI 라이브러리**: React 18.2.0, TailwindCSS
- **현재 상태**: 주로 일본어로 작성된 UI 텍스트
- **이미 한글화된 부분**:
  - `systemPromptConstants.ts`: AI 시스템 프롬프트 (✅ 완료)
  - `messageInputContainer.tsx`: 음성 인식 언어 설정 (ko-KR)
  - `index.tsx`: 일부 주석
  - `README.md`: 부분적 한글화 (일부 일본어 잔존)

## 3. 권장 한글화 전략

### 방법 A: 직접 한글화 (현재 진행 중)
**장점:**
- 즉시 적용 가능
- 추가 라이브러리 불필요
- 단순하고 명확함

**단점:**
- 언어 전환 불가능
- 유지보수 시 번역 수정이 코드 수정 필요

**적용 시나리오:**
- 한국 사용자만 대상
- 빠른 프로토타입 필요
- 단순한 프로젝트 구조 유지

### 방법 B: i18n 라이브러리 도입
**권장 라이브러리:**
- `next-i18next` (Next.js 공식 권장)
- `react-intl` (React용 국제화 라이브러리)

**장점:**
- 다국어 지원 (일본어 ↔ 한국어 ↔ 영어)
- 언어 전환 기능 제공
- 번역 파일 분리로 관리 용이
- 추후 확장성 좋음

**단점:**
- 초기 설정 복잡
- 프로젝트 구조 변경 필요
- 추가 의존성

**적용 시나리오:**
- 다국어 지원 필요
- 장기 프로젝트
- 팀 협업으로 번역 관리

## 4. 단계별 한글화 작업 순서

### Phase 1: 핵심 UI (1-2시간)
1. ✅ `systemPromptConstants.ts` - **완료**
2. `introduction.tsx` - 첫 화면 안내
3. `messageInput.tsx` - 메시지 입력란
4. `index.tsx` - 에러 메시지

### Phase 2: 설정 및 메뉴 (1-2시간)
5. `settings.tsx` - 설정 화면 전체
6. `menu.tsx` - 메뉴 레이블
7. `chatLog.tsx` - 대화 로그

### Phase 3: 메타데이터 및 문서 (30분)
8. `meta.tsx` - 페이지 메타데이터
9. `README.md` - 완전 한글화

### Phase 4: 주석 및 polish (선택, 1-2시간)
10. 모든 파일의 주석 및 에러 메시지
11. placeholder, label 등 미세 조정
12. 테스트 및 확인

## 5. 주의사항

### 번역 일관성 유지
- **API Key**: "API 키" (일관되게 사용)
- **Character**: "캐릭터"
- **Setting**: "설정"
- **Chat Log**: "대화 로그" 또는 "대화 내역"
- **System Prompt**: "시스템 프롬프트"
- **Voice**: "음성"

### 기술 용어
다음은 번역하지 않고 원문 유지 권장:
- VRM
- ChatGPT API
- OpenAI
- ElevenLabs
- Voice ID
- API Key 형식 (sk-...)

### 문체
- **존댓말 사용**: "~해주세요", "~입니다"
- **명확하고 친절한 톤**: 사용자 친화적
- **간결함**: 불필요한 설명 제거

## 7. 다음 단계 제안

### 즉시 실행 (직접 한글화)
현재 방식대로 파일별로 일본어를 한글로 직접 교체
→ **빠르고 간단, 한국 사용자 전용 앱에 적합**

### 장기 계획 (i18n 도입)
1. `next-i18next` 설치 및 설정
2. 번역 파일 생성 (`public/locales/ko`, `public/locales/ja`)
3. 컴포넌트에서 `useTranslation` hook 사용
4. 언어 선택 UI 추가
→ **다국어 지원, 확장 가능, 프로덕션 레벨**

## 8. 예상 작업 시간
- **직접 한글화**: 4-6시간 (Phase 1-3)
- **i18n 도입**: 8-12시간 (설정 + 번역 + 테스트)

## 결론
현재 프로젝트는 이미 부분적으로 한글화가 진행되었으며, 사용자 대면 UI 텍스트만 완전히 한글화하면 한국 사용자를 위한 완성도 높은 애플리케이션이 될 것입니다. 

**다국어 지원이 필요하지 않다면** → 직접 한글화 (빠름, 간단)
**향후 일본어/영어 지원 고려** → i18n 라이브러리 도입 (체계적, 확장 가능)
